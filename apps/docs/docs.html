Documentation

Install Ding, mount a toaster, and show your first notification.

Install Ding

Choose your framework

There is no stylesheet to import: styles are injected from JavaScript.

npm i @yusufceng1z/ding-react

Using shadcn/ui? This installs the package and adds a ding-toaster.tsx wrapper:

npx shadcn@latest add @ding/ding
npm i @yusufceng1z/ding-svelte
npm i @yusufceng1z/ding-vue
npm i @yusufceng1z/ding

Your first toast

Add this example to your app after installing Ding. Mount the toaster once near the root, then click Save to show a notification.

import { Toaster, toast } from '@yusufceng1z/ding-react';

export default function App() {
  return (
    <>
      <Toaster />
      <button onClick={() => toast.success('Saved')}>Save</button>
    </>
  );
}
<script>
  import { Toaster, toast } from '@yusufceng1z/ding-svelte';
</script>

<Toaster />
<button onclick={() => toast.success('Saved')}>Save</button>
<script setup>
import { Toaster, toast } from '@yusufceng1z/ding-vue';
</script>

<template>
  <Toaster />
  <button @click="toast.success('Saved')">Save</button>
</template>
<!-- index.html in a Vite app -->
<button id="save">Save</button>

<script type="module">
  import { mountToaster, toast } from '@yusufceng1z/ding';

  mountToaster();
  document.querySelector('#save').addEventListener('click', () => {
    toast.success('Saved');
  });
</script>

Nuxt

Toaster draws nothing in place and starts after the page has loaded, so server rendering is safe. Put it in app.vue and call toast from client code, like a click handler or onMounted:

<!-- app.vue -->
<template>
  <Toaster position="top-center" theme="system" />
  <NuxtPage />
</template>

<script setup>
import { Toaster } from '@yusufceng1z/ding-vue';
</script>

Next.js

The package is marked "use client", so Toaster goes straight into app/layout.tsx, which stays a server component:

import { Toaster } from '@yusufceng1z/ding-react';

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en">
      <body>
        {children}
        <Toaster position="top-center" theme="system" />
      </body>
    </html>
  );
}

Call toast from client components only. The Next.js guide covers server actions. With the Pages Router, render <Toaster /> in pages/_app.tsx.

Show a toast

Import toast from the same package and call it from anywhere. Calls like toast.success() and toast.loading() return a toast ID you can pass to toast.update() or toast.dismiss(). toast.loading(title) works the same and stays until you update or dismiss it.

import { toast } from '@yusufceng1z/ding-react@yusufceng1z/ding-svelte@yusufceng1z/ding-vue@yusufceng1z/ding';

toast.success('Saved');
toast.error('Payment failed', { description: 'Card declined' });
toast.warning('Storage almost full');
toast.info('New version available');

Only one toast is visible at a time. A new call morphs the toast on screen instead of stacking a second one. Repeating the same toast adds a counter (×2).

Update in place

Wrap a promise to move a toast from loading to the result. toast.promise() returns that same promise, so you can await it to get the result or catch a rejection.

toast.promise(save(), {
  loading: 'Saving…',
  success: 'Saved',
  error: (err) => `Could not save: ${err.message}`,
});

Or update by hand, for progress and other long jobs:

const id = toast.loading('Uploading photo…', { progress: 0 });
toast.update(id, { progress: 0.6 });
toast.update(id, { type: 'success', title: 'Photo uploaded', progress: null });

Only the newest caller can update the shared toast, so a slow request that finishes late cannot overwrite a newer message.

Actions

An onClick may return a patch. The toast then morphs in place instead of closing. A returned patch removes the buttons unless it names them again.

toast.success('Message deleted', {
  action: {
    label: 'Undo',
    onClick: () => {
      restore();
      return { type: 'info', title: 'Restored' };
    },
  },
});

Options

description
Second line of text.
action
{ label, onClick }. The main button.
secondary
{ label, onClick }. A quieter button beside the action.
image
Avatar or thumbnail URL. Replaces the status icon.
meta
Small trailing text, such as “now” or “⌘V”.
progress
0 to 1. Draws a thin bar at the bottom of the toast.
duration
Milliseconds before it closes. 0 keeps it until dismissed. Default 5000.
id
Reuse an id so repeated calls from one place stay one caller.

Errors, loading toasts and toasts with a button stay until dismissed, so nobody misses something they need to act on. Hover and keyboard focus pause the timer.

Configure

toast.configure({
  position: 'bottom-right', // top-left, top-center, top-right, bottom-left, bottom-center, bottom-right
  theme: 'dark',            // system, light, dark
  labels: { dismiss: 'Fermer la notification' }, // screen reader names, English by default
  sound: true,
  volume: 0.5,
});

toast.dismiss(id);  // one toast
toast.dismiss();    // all

Position, theme and labels can also be set as props on the toaster. The toast follows reading direction, so right-to-left pages mirror automatically.

labels sets the names screen readers announce for the notifications region (region) and the close button (dismiss). Keys you leave out keep their English default, so a non-English page only needs to translate what it uses.

Content Security Policy

Styles are injected as one <style> element. If your CSP blocks inline styles (style-src without 'unsafe-inline'), pass the page's nonce. Per-toast values are set through the DOM, which CSP allows, so the stylesheet is the only thing that needs it.

<Toaster nonce={nonce} />
<Toaster nonce={nonce} />
<Toaster :nonce="nonce" />
mountToaster({ nonce });

In Next.js, read the nonce your proxy sets with (await headers()).get('x-nonce') in a server component and pass it down.

Styling

Open the playground to try these styles on a live toast and copy the CSS.

Colors and corner radius are CSS variables. Set them in your own stylesheet and they apply to every toast, whatever framework you use.

.tst-viewport {
  --tst-radius: 8px;
  --tst-bg: #1e3a8a;
  --tst-fg: #fff;
  --tst-success: #16a34a;
}

--tst-radius22pxCorner radius. The default makes a pill
--tst-bglight-dark(#fff, #0c0c0d)Background
--tst-fglight-dark(#0f0f13, #fafafa)Text
--tst-successlight-dark(#12a36b, #4ade80)Success icon
--tst-errorlight-dark(#e5484d, #f87171)Error icon
--tst-warninglight-dark(#c77d00, #fbbf24)Warning icon

Advanced styling

More hooks, for when colors and radius are not enough. The font comes from .tst-viewport, so set font-family and font-size there.

VariableDefaultControls
--tst-size44pxHeight of the pill and width of the icon circle
--tst-pad16pxDistance from the screen edge
--tst-shadowbuilt inShadow around the toast
--tst-enter-scalebuilt inHow small the toast starts when it arrives

Filled toasts. Each toast exposes --fill (surface), --on (text, buttons, close button, focus ring) and --c (icon color) per status. Override them to fill the toast with its status color.

.tst-viewport .tst[data-type=error] { --fill: #e5484d; --on: #fff; --c: #fff; }

Light and dark. Ding follows the system by default. If your site has its own theme switch, such as a .dark class, pass the current theme with <Toaster theme={theme} /> or toast.configure({ theme }). Give a color two values with light-dark(), and it picks the one for the active theme.

.tst-viewport .tst[data-type=error] { --fill: light-dark(#dc2626, #7f1d1d); --on: #fff; --c: #fff; }

One toast, one style. Pass className and style it as .tst.your-class. toast.update(id, { className: null }) removes it.

toast.success('Saved', { className: 'big' });

Springs. Retune the three motions with { stiffness, damping }. Leave one out to keep its default (enter 320/26, morph 340/27, stack 400/36). Applies to toasts shown afterwards.

toast.configure({ springs: { enter: { stiffness: 220, damping: 14 } } });

Icons. Replace a status icon with SVG path strings on a 24×24 grid, drawn as strokes. The first path is the outer ring. Keep three paths for warning and info, since their animations target the second and third.

toast.configure({ icons: { success: ['M12 3a9 9 0 1 0 0 18a9 9 0 1 0 0-18', 'M8 12l3 3 5-6'] } });

The defaults follow the theme through light-dark(). A single value applies to both themes. To keep them apart, write your own: --tst-bg: light-dark(#fff, #111).

Sound

Off by default. Turn it on and each status gets its own soft tone: success rises, error falls, warning double-taps, info is a single note. Loading is silent, and progress updates never make a sound.

toast.configure({ sound: true, volume: 0.5 });

Browsers keep audio locked until a click or key press, so the first sound has to follow one. To use your own sounds or a sound library, pass a function. It receives success, error, warning, info or loading, once per new toast and once per status change.

toast.configure({ sound: (type) => mySounds.play(type) });

Accessibility

  • Messages go through persistent live regions: errors are announced assertively, everything else politely.
  • Esc dismisses. Alt + T moves focus into the toast.
  • Respects prefers-reduced-motion.
  • Buttons stay out of the tab order until the toast has opened.
