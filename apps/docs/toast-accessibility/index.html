Making toast notifications accessible

A toast that a screen reader never announces, or that disappears before a keyboard user can reach its button, does not work. These are the four things to check.

Announce it

Put the text in a live region so screen readers read it without moving focus. role="status" is polite and fits most messages. role="alert" interrupts, so keep it for urgent errors. Ding announces errors assertively and everything else politely. Live-region support varies between screen readers, so test with the ones your users have.

Give people time

A message on a timer is a problem for anyone who reads slowly or needs longer to react. Pause the timer on hover and on keyboard focus, keep toasts with buttons on screen longer, and do not auto-dismiss errors. In Ding, errors, loading toasts and toasts with a button stay until dismissed.

Keyboard access

If a toast has a button, keyboard users need a way to reach it. In Ding, Alt + T moves focus into the toast and Esc dismisses it.

Reduced motion

Spring animation looks good and some people turn motion off. Ding follows prefers-reduced-motion.

What a library cannot do for you

Do not let a toast be the only place a critical message or an Undo lives. Keep the text short and plain. See toast notification UX for when a toast is the right choice, and undo toast for a pattern that needs a second way back.

Which WCAG criteria apply

  • 4.1.3 Status Messages (AA): a message must be announced without taking focus, which is what a live region does.
  • 2.2.1 Timing Adjustable (A): if content disappears on a timer, people need a way to extend or stop it.
  • 2.2.2 Pause, Stop, Hide (A): anything that moves or updates on its own for more than five seconds needs a way to pause it.
  • 1.4.1 Use of Color (A): status needs a second cue, such as an icon or text.

What Ding does for you

  • Messages go through persistent live regions: errors are assertive, everything else is polite.
  • Esc dismisses. It does nothing while a dialog, menu or text field has focus, so it does not steal the key.
  • Alt + T moves focus into the toast.
  • Hover and keyboard focus pause the timer. Errors, loading toasts and toasts with a button stay until dismissed.
  • Motion respects prefers-reduced-motion, and the toaster mirrors on right-to-left pages.
  • The region and close button names can be localized with the labels option.

Frequently asked questions

Should a toast take keyboard focus?

Usually not, because it would interrupt what the user is doing. Announce it through a live region and offer a shortcut, such as Alt + T in Ding, to reach it.

Is role=alert right for every toast?

No. alert is assertive and interrupts the screen reader. Use it for errors and a polite status region for everything else.

How long should a toast stay?

Long enough to read it, and anything with a button should wait for the user. See toast notification UX.

Can I translate the labels?

Yes. Pass labels to toast.configure or to Toaster: region and dismiss keep their English defaults unless you set them.
