Next.js toast notifications

The package is marked "use client", so the Toaster goes straight into your root layout. The one rule: call toast from client code. Everything else is the same as plain React.

Try it:

Install

npm i @yusufceng1z/ding-react

Add the Toaster to the layout

Render it once in app/layout.tsx. The layout stays a server component, no wrapper file needed.

import { Toaster } from '@yusufceng1z/ding-react';

      export default function RootLayout({ children }: { children: React.ReactNode }) {
        return (
          <html lang="en">
            <body>
              {children}
              <Toaster position="top-center" theme="system" />
            </body>
          </html>
        );
      }

Call toast from client code

"use client";

      import { toast } from '@yusufceng1z/ding-react';

      export function SaveButton() {
        return <button onClick={() => toast.success('Saved')}>Save</button>;
      }

Server actions

toast runs in the browser, so it cannot be called inside a server action. Call it from the client code that triggers the action and pass the action's promise:

toast.promise(saveAction(formData), {
        loading: 'Saving…',
        success: 'Saved',
        error: 'Could not save',
      });

With the Pages Router, render <Toaster /> in pages/_app.tsx. If the project uses shadcn/ui, the shadcn install also works. For the non-Next parts see React toast notifications.

Theme and styling

Ding follows the system theme by default. If your site has its own theme switch, such as a .dark class, pass the current theme to the toaster:

<Toaster theme={theme} position="top-center" />

Colors and corner radius are CSS variables, so a global stylesheet is enough to match your design:

.tst-viewport {
  --tst-radius: 8px;
  --tst-bg: #1e3a8a;
  --tst-fg: #fff;
  --tst-success: #16a34a;
}

Content Security Policy

Styles are injected as one <style> element. If your CSP blocks inline styles, pass the request nonce with <Toaster nonce={nonce} />. Per-toast values are set through the DOM, so only the stylesheet needs the nonce.

Frequently asked questions

Do I need a client component wrapper?

No. The package ships "use client", so Toaster can go into app/layout.tsx as it is.

Can I call toast from a server component or server action?

A toast is shown in the browser, so call toast from client code, for example after a server action resolves. The server actions section above shows the pattern.

Does it work with a theme switcher?

Yes. Pass the current theme to Toaster or call toast.configure({ theme }).

Is there a shadcn/ui version?

Yes. npx shadcn@latest add @ding/ding installs the React package and adds a ding-toaster.tsx wrapper. See the shadcn/ui toast guide.
