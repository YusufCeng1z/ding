A react-hot-toast alternative

react-hot-toast has a small, friendly API, and Ding keeps that feel. The difference is that Ding keeps one toast on screen and morphs it, where react-hot-toast keeps several.

Try it:

Same kind of API

import { toast } from '@yusufceng1z/ding-react';

      toast.success('Saved');
      toast.error('Payment failed');
      toast.promise(save(), { loading: 'Saving…', success: 'Saved', error: 'Failed' });

Render <Toaster /> once near the root, the same way you do today.

What changes

A second call does not add a second toast. The visible one changes into the new message. You can also update a toast yourself with toast.update(id, patch), which makes progress bars and multi-step jobs easy, and sound is available if you want it (off by default).

Ding also ships a Svelte 5 package and a framework-free one, in case you work in more than one stack.

Install

npm i @yusufceng1z/ding-react

Full setup is on the React toast page, and a comparison with a stacking alternative is on the Sonner page.

For these everyday calls, switching is mostly a change of import. Options and custom rendering differ, so check yours against the docs.

What you get in return

  • Spring-based motion that keeps its momentum when interrupted.
  • A toast that changes in place, from loading to success or error.
  • No stylesheet to import and no dependencies.
  • Svelte 5, Vue 3 and plain JavaScript versions, not only React.

Frequently asked questions

Is Ding a drop-in replacement for react-hot-toast?

For toast.success, toast.error, toast.promise and toast.dismiss the call shape is the same. Other options differ, so test the ones you use.

Does Ding need a stylesheet?

No. Styles are injected from JavaScript.

Can I restyle the toast?

Yes. Colors and corner radius are CSS variables, and the playground generates the CSS for you.

Does it work in the Next.js App Router?

Yes. See the Next.js toast guide.
