React toast notifications

Ding is a React toast library with no dependencies and no stylesheet. You render one component and call a function. This page covers the setup and the parts people usually ask about next.

Try it:

Install

One package, nothing else to add.

npm i @yusufceng1z/ding-react

Render the Toaster once

Put it near the root of the app. The styles are injected from JavaScript, so there is no CSS file to import.

import { Toaster } from '@yusufceng1z/ding-react';

      export default function App() {
        return (
          <>
            <Toaster position="top-center" theme="system" />
            {/* your app */}
          </>
        );
      }

Call toast from anywhere

toast is a plain function, so it works in event handlers, effects, data-fetching code and anything else that is not a component.

import { toast } from '@yusufceng1z/ding-react';

      toast.success('Saved');
      toast.error('Payment failed', { description: 'Card declined' });

Only one toast is on screen. If you call toast again while one is showing, the toast on screen changes into the new message. Calling it with the same message twice adds a counter (×2) instead of a second toast.

Saving, loading and undo

For a request, pass the promise and one toast goes from loading to the result. The loading toast page has the details.

toast.promise(save(), {
        loading: 'Saving…',
        success: 'Saved',
        error: (err) => `Could not save: ${err.message}`,
      });

An action button can return a patch, which is how undo toasts confirm that the undo worked.

Next.js and shadcn/ui

The package is marked "use client", so in the Next.js App Router Toaster can go straight into a server layout. The Next.js setup shows how. If the project uses shadcn/ui, there is also a one-command install.

Timing

Plain toasts close after 5 seconds. Errors, loading toasts and toasts with a button stay until the user dismisses them, because those are the ones people must not miss. Hovering or focusing a toast pauses the timer.

I wrote Ding because I wanted a toast that does not pile up. If that sounds like what you need, a star on GitHub helps others find it.

Position, theme and sound

The toaster takes its settings as props, and the same settings work from anywhere with toast.configure:

<Toaster position="bottom-right" theme="dark" />

toast.configure({ sound: true, volume: 0.5 });

There are six positions (top and bottom, each left, center or right) and three themes: system, light and dark. The toaster mirrors itself on right-to-left pages.

Restyle it with CSS variables

Colors and corner radius are CSS variables, so you can match your design system without touching the library:

.tst-viewport {
  --tst-radius: 8px;
  --tst-bg: #1e3a8a;
  --tst-fg: #fff;
  --tst-success: #16a34a;
}

Try the options live in the playground, which also gives you the CSS to copy.

Frequently asked questions

Do I need to import a CSS file?

No. Ding injects its styles from JavaScript, so there is nothing to import. If your Content Security Policy blocks inline styles, pass the page's nonce with <Toaster nonce={nonce} />.

Which React versions does Ding support?

React 18 and newer, through @yusufceng1z/ding-react.

Does Ding work with the Next.js App Router?

Yes. The package ships "use client", so Toaster can go straight into app/layout.tsx. See the Next.js toast guide.

Does Ding have dependencies?

No third-party dependencies. The React package renders on top of the small Ding core.

How do I update a toast instead of showing a new one?

Keep the id that toast.loading returns and call toast.update(id, { type: 'success', title: 'Saved' }), or wrap a promise with toast.promise.
