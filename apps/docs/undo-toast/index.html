How to build an undo toast

A confirm dialog before every delete slows people down and they click through it anyway. Doing the action and offering Undo in a toast is faster, and safer if the undo actually works.

Try it:

The code

import { toast } from '@yusufceng1z/ding-react';

      toast.success('Message deleted', {
        action: {
          label: 'Undo',
          onClick: () => {
            restore();
            return { type: 'info', title: 'Restored' };
          },
        },
      });

The click handler may return a patch. When it does, the toast changes in place to Restored instead of closing, so the person gets confirmation that the undo worked. The same code works with @yusufceng1z/ding-svelte and @yusufceng1z/ding, only the import differs.

Making the undo real

Do not delete for good when the button is shown. Mark the item as deleted first, and remove it only after the undo window has passed, or never, if you keep a trash. Otherwise Undo is a promise you cannot keep when the request has already finished.

A toast with a button stays until dismissed in Ding, so nobody is racing a timer. Still, keep a second way back, such as a trash view. A toast is easy to miss, and for some people it is hard to reach, see toast accessibility.

More on when toasts are the right tool: toast notification UX.

Morph the toast after Undo

An onClick can return a patch. The toast then changes in place instead of closing, so the user sees that the undo worked:

toast.success('Message deleted', {
  action: {
    label: 'Undo',
    onClick: () => {
      restore();
      return { type: 'info', title: 'Restored' };
    },
  },
});

Give the undo a time limit

A toast with a button stays until dismissed. Set duration to close it after a time limit, and a thin countdown line shows how long is left:

toast.success('Message deleted', {
  duration: 8000,
  action: { label: 'Undo', onClick: restore },
});

Frequently asked questions

Why use undo instead of a confirmation dialog?

People confirm out of habit. Doing the action at once and offering undo is faster, and a mistake is still easy to reverse.

How long should the undo window be?

Long enough to notice and react, often several seconds. Set it with duration. Hover and keyboard focus pause the timer.

Can the toast change after the user clicks Undo?

Yes. Return a patch from onClick, for example { type: 'info', title: 'Restored' }.

When is undo not enough?

For actions that cannot be reversed or that affect other people, ask first. See toast notification UX.
